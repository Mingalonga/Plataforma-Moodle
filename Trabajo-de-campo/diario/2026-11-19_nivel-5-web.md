# Diario · 19 de noviembre de 2026 · Nivel 5: web con inicio de sesión

- **Horario:** 16:10 a 17:40, con una pausa.
- **Objetivo:** convertir el programa del nivel 4 en una pequeña web con usuario y contraseña que muestre la vista centralizada de las dos aulas.
- **Resultado:** conseguido. La web pide usuario y contraseña y enseña las dos aulas, las 15 personas y las 13 cuentas para revisar, con el estilo de ATU (TC-23, TC-24).

## Qué he hecho

1. **Elegir Flask.** El nivel 4 no usaba librerías externas, pero una web con sesiones, cookies y contraseñas hecha a mano es la forma más fácil de dejar un agujero. Flask es pequeño, muy usado y está mantenido. Lo instalé en un **entorno virtual** (`.venv`), una "caja" de Python solo para el proyecto, con **versiones exactas** (`requirements.txt`).
2. **Renombrar la carpeta** a `herramienta/`: a partir de ahora es una sola herramienta que crece nivel a nivel.
3. **Cuentas de la web** (`cuentas_web.py`, `crear_usuario.py`): la contraseña nunca se guarda, solo su huella (hash). Creé mi usuario.
4. **La web** (`web.py`): tres páginas (entrar, salir y la vista). **No sabe hablar con Moodle**: reutiliza sin cambios `centralizar.py`, `moodle_api.py` e `informe.py` del nivel 4.
5. **Estilo propio** a partir del logo de ATU (ver abajo).

Código y lista de medidas de seguridad en [`laboratorio/herramienta/`](../laboratorio/herramienta/).

## Seguridad de la web

| Riesgo | Medida |
|---|---|
| Robo del archivo de cuentas | Solo huellas scrypt, archivo fuera del código y con permisos 600 |
| Adivinar qué usuarios existen | Mismo mensaje de error y mismo tiempo de respuesta exista o no el usuario |
| Probar contraseñas sin parar | 5 fallos bloquean 5 minutos; cada intento queda registrado |
| Falsificar la sesión | Cookie firmada con clave aleatoria; `HttpOnly`, `SameSite=Strict`, 30 minutos |
| Otra web envía formularios en mi nombre (CSRF) | Token secreto en cada formulario, también en «Salir» |
| Meter código en la página (XSS) | Jinja escapa todos los datos y la CSP no deja cargar nada de fuera |
| Datos personales guardados en el navegador | `Cache-Control: no-store` |
| Acceso desde otros equipos | Solo escucha en `127.0.0.1` y sin modo depuración |

Para producción faltaría, como mínimo, HTTPS, un servidor de verdad en vez del de pruebas de Flask y entrar con Microsoft 365 (nivel 7).

## Estilo: que no parezca una plantilla genérica

Pedí que el diseño fuera limpio y fácil de leer, pero que no tuviera el aspecto típico de "hecho por IA" (todo con las mismas esquinas redondeadas, los mismos colores...). La solución fue sacar todo del logo de ATU:

- **Colores** medidos del archivo del logo: marino `#1A2E76`, azul `#163DCD` y blanco.
- **Esquinas cortadas a 45°** en vez de redondeadas, como el octógono y la "a" del logo, y solo en dos esquinas opuestas.
- El **corchete** del logo marca cada título de sección.
- **Tipografías** con esquinas cortadas para títulos (Chakra Petch) y técnica para el texto (Barlow), libres (OFL) e incluidas en la herramienta, sin cargarlas de Google.
- Los estados se distinguen por **color y texto**, nunca solo por color.

Es CSS puro, sin herramientas extra, con los colores definidos una sola vez. Antes de dárselo a la tutora o a ATU habría que confirmar que se puede usar su logo; por eso el archivo del logo no está en el repositorio.

## Problemas y dudas

| Qué pasó | Causa | Solución |
|---|---|---|
| El mensaje con las plantillas no se podía enviar por el chat | El chat bloquea texto con etiquetas HTML que cargan recursos | Descargar los archivos del repositorio con `curl` |
| El logo no estaba en Descargas | No se llegó a descargar | Copiar el archivo original |
| No me dejaba entrar | Sin confirmar; probablemente el usuario guardado en el gestor de contraseñas no coincidía (aparece `adminstrador`) | Volver a escribirlo bien. Como escribí la contraseña en el chat, la doy por quemada y la cambio con `crear_usuario.py` |

## Qué he aprendido

- Lo modular funciona: la web se hizo sin tocar ni una línea de las piezas del nivel 4.
- Un entorno virtual aísla las librerías del proyecto y fijar versiones evita sorpresas.
- La mayoría de la seguridad de una web está en detalles que no se ven: cómo se guardan las contraseñas, la cookie, los tokens de formulario y las cabeceras.
- Las plantillas Jinja se parecen a PHP mezclado con HTML, pero escapan los datos solas.
